# Prompt: Notifications Center — KorraStore

## Goal

Build `/notifications`: an in-app list of the buyer's important updates (purchase,
order, resale, buyback, price-related), backed by the same `notifications` outbox
table used for email/SMS delivery (`AGENTS.md` §15), with an in-app `channel`
alongside `email`/`sms`. Desktop + mobile, light mode only.

## Skills read

- `.agents/skills/supabase/SKILL.md` — `notifications` table reads scoped to the
  owning user, mark-as-read writes.
- `02-design-system.md` — `Card`, `Badge`, `EmptyState`, `Pagination`.
- `AGENTS.md` §15 (notification outbox pattern, channels).

## Existing code inspected

- `03-database-schema.md` — `notifications` schema; confirm it supports an
  in-app `channel` value (`'in_app' | 'email' | 'sms'`) alongside the
  email/SMS channels used by `30-notifications-email-sms.md` — if the table was
  scoped to email/SMS only, add the `in_app` channel value here rather than
  forking a second table.

## Decisions / assumptions

- **In-app notifications are created by the same domain events** as email/SMS
  (order status change, resale sold, buyback status change, price-related updates)
  — this prompt adds the `in_app` channel as a first-class option alongside the
  outbox pattern, not a separate notification system.
- **Read/unread state** is tracked per notification; a small unread-count badge
  appears on the nav rail/bottom tab bar's notifications icon (coordinate with
  `47-mobile-navigation.md`/`48-desktop-navigation.md`).
- **Clicking a notification** navigates to the relevant page (order detail, resale
  listing, buyback request) and marks it read.

## Visual interpretation (light mode only)

### Layout — Desktop (≥1024px)
Content max-width ~640px. H1 "Notifications" + a "Mark all as read" text action.
List of notification rows (`Card`, unread rows have a subtle Harvest Wheat-tinted
left border or dot indicator): icon by type, short message, relative timestamp,
tap/click target for the whole row.

### Layout — Mobile (<640px)
Same rows, full width, "Mark all as read" as a compact icon-button in the header.

### Empty state
No notifications yet → `EmptyState` ("Nothing here yet — updates about your orders
and activity will show up here").

## Implementation requirements

- Reads scoped to `auth.uid()`.
- Unread-count query is cheap enough to run on every page load for the nav badge —
  use an indexed count query, not a full row fetch.
- `"use client"` scoped to the mark-as-read interactions.

## Security requirements

- A user can only read/mark their own notifications.

## Acceptance criteria

- List shows real notifications generated by domain events (order/resale/buyback/
  price updates) once those flows exist.
- Unread state and count badge update correctly on read.
- Clicking a notification navigates correctly and marks it read.
- Layout matches spec at mobile/desktop.

## Checks to run

- `npm run typecheck`, `npm run lint`, `npm run build`.

## Manual test steps

1. `npm run dev`; sign in as a buyer with at least one order/resale/buyback event
   that generated a notification; visit `/notifications`.
2. Confirm unread rows are visually distinct and the nav badge shows the correct
   count.
3. Click a notification; confirm navigation to the right page and the row becomes
   read.
4. Use "Mark all as read"; confirm all rows update and the badge clears.
5. Resize to ~375px and ~1440px — confirm layout matches spec.
